# SCAL 项目全盘计划

> 基于用户原文重建。这是给 Codex 的完整原始需求，流程地图只是其中一部分。

---

## 总体目标

构建一个 **SCAL 生产制造系统的完整知识库**，以超大交互式 HTML 流程图为核心载体，把 PDA 前端、PDA 后端、Web MES(BS)、桌面 MES(CS)、数据库、文档 Demo 六大来源的信息全部整合在一起。

---

## 一、核心交付：超大交互式流程图（HTML）

### 1.1 主链路（7 块，线性）

```
采购 → 入库 → 质检 → 称料 → 上料 → 配置产出 → 结案
```

> ⚠️ 用户原文写为「上料→称料」，后口头纠正为「先称料，才能上料」。正确顺序：称料(4) → 上料(5)。

### 1.2 子流程（每块内部多个子流程，块与块之间首尾衔接）

以采购→入库为例：

```
采购
  └→ 条码申请
  └→ 标签分发
  └→ 扫码入库 ──→ (衔接质检)
                     └→ 抽样标签
                     └→ ...
```

每个子流程的**结束**连接下一个主流程块的**起始**子流程。

### 1.3 交互体验

| 层级              | 交互                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| 首屏              | 7 个主流程块从左到右线性排列，隐约可见缩小的子流程块（低强调、不抢眼） |
| 点击主流程块/热点 | 视口放大到该局部，展开子流程和连接线                                   |
| 子流程节点        | 可展开证据信息：归属系统(BS/CS/PDA/DB)、源码模块、接口、表、存储过程   |
| Demo 链接         | 可点击跳转到业务 Demo 页面（如采购条码申请页）                         |
| 视觉风格          | 沉稳商务、系统泳道、定向连接器、高信息密度、无装饰噪音                 |

## 三、整合目标

流程地图不只是画图。最终的想法是：

- 点击某个局部流程节点（比如「采购条码申请」）→ 可以连接到 Demo 示例页
- Demo 示例就是 `business/` 下对应的业务页面（如采购条码申请页面示例）
- 数据库表字段文档（`tables/` 下 621 张表）也要整合进流程上下文
- 源码模块、接口、存储过程 —— 全部可追溯

**本质上是把 6 个数据源的知识编织成一个结构化的、可导航的知识库。**

## 四、工作步骤

```
第1步：盘点 6 个源码源，识别业务模块、API、数据库制品、文档、Demo
第2步：验证每个主阶段的子流程及其顺序
第3步：为每个子流程记录前驱/后继/参与系统/实现证据/数据实体/可选 Demo
第4步：建模为结构化流程数据，HTML 地图基于验证关系生成
第5步：构建交互式 HTML（总览 + 阶段详情），挂接源码证据和 Demo 链接
第6步：与流程负责人审查缺口、模糊过渡、跨系统交接点
```
